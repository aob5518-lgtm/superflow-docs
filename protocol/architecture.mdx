# 系统架构

<Frame>
  <img src="/images/architecture.svg" alt="SuperFlow Protocol System Architecture" />
</Frame>

SuperFlow Protocol 是一个 AI-Driven Trading Operating System。

它将交易过程拆分为账户系统、资金系统、AI 决策系统、智能路由系统、执行系统、收益系统与验证系统，并通过 SUPER AGENT 进行统一调度。

## 核心架构模型

SuperFlow 的系统架构可以理解为一个从用户入口到真实交易执行，再到收益验证的完整闭环。

```text
User
  ↓
Account System
  ↓
Capital System
  ↓
SUPER AGENT
  ↓
Smart Routing
  ↓
Execution Layer
  ↓
Yield System
  ↓
Verification System
```

## 模块关系

| 模块 | 核心作用 | 系统意义 |
| --- | --- | --- |
| Account System | 管理账户状态与用户权限 | 让用户进入系统 |
| Capital System | 管理资金状态与调度能力 | 让资金成为可调度资源 |
| SUPER AGENT | 进行 AI 决策、执行调度与风险控制 | 让交易能力系统化 |
| Smart Routing | 优化交易路径、成本与执行效率 | 让执行过程更智能 |
| Execution Layer | 完成真实市场交易 | 让系统连接真实市场 |
| Yield System | 记录和计算收益结果 | 让收益形成系统模型 |
| Verification System | 提供交易凭证与验证入口 | 让结果可被追溯 |

## 系统运行流程

<Steps>
  <Step title="用户进入系统">
    用户不再直接面对复杂交易环境，而是通过 SuperFlow 进入统一的交易能力系统。
  </Step>

  <Step title="资金进入状态管理">
    用户资金进入 Capital System 后，被系统识别为可调度资源，而不是静态余额。
  </Step>

  <Step title="SUPER AGENT 进行决策">
    SUPER AGENT 根据市场状态、账户状态、资金状态与风险状态进行综合判断。
  </Step>

  <Step title="Smart Routing 优化路径">
    系统根据成本、深度、速度、滑点与平台状态，选择更适合的交易执行路径。
  </Step>

  <Step title="Execution Layer 完成执行">
    执行层负责将交易意图转化为真实订单，并同步执行结果。
  </Step>

  <Step title="Verification System 生成凭证">
    系统将交易结果、收益记录与关键执行信息沉淀为可验证凭证。
  </Step>
</Steps>

## 为什么 SuperFlow 是系统，而不是工具？

普通交易工具通常只解决一个局部问题：

- 行情展示
- 下单操作
- 策略信号
- 收益统计
- 资产页面

但真实交易需要的是一套完整系统。

SuperFlow 的设计目标，是将交易过程中的判断、执行、风控、资金管理、收益记录与凭证验证全部纳入统一架构中。

## 核心结论

SuperFlow 不是一个交易入口。

SuperFlow 是一个将交易能力抽象为系统能力的链上交易操作系统。
